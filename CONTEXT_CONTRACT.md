# Context contract (v1)

The paste payload is the exact stored clipboard value. Source and destination evidence may help select an item; it never edits that value. A copied image or file keeps its existing asset semantics.

- **Source** is the app correlated with an observed ⌘C and a pasteboard change within 800 ms. The key monitor is asynchronous; callbacks more than 150 ms late or delivered after a clipboard poll are discarded. The callback app must match the last foreground process sampled by Jev, and a recorded activation between key-event time and callback makes source unknown. A switch after the callback can still leave the observed source intact. This is an inference, not proof of the writer; an unobserved rapid focus round trip remains a public API limit. **Writer** is Jev Clipboard only for its own pasteboard writes and restores. **Foreground at poll** is an observation, never an automatic source. `org.nspasteboard.source` is an unauthenticated declaration; a discrepancy makes source unknown. Menu, background, delayed, remote and transformed copies may be unknown.
- Older library entries keep their displayed `app` value for compatibility, but without provenance that value is sent to selection as unknown source.
- Selection and label evidence is attached only when the source app's focused AX selection exactly matches the copied text, allowing only CRLF to LF line-ending normalization. A selected range of at most 1024 UTF-16 units is required before reading selected text. An unmatched copy button payload gets no surrounding field claim. AX denial, missing selection/range, secure input, or custom UI falls back to payload only. Capture is read-only, focused-element only, and bounded by short AX timeouts and 100-character stored labels/window titles. There is no screenshot or background tree traversal.
- One established source app, window, label and app-provided AX identifier can refresh an exact text occurrence. Without that identifier, repeated copies stay separate. Different or uncertain sources remain separate bounded history entries. Candidate selection presents only one ordinary entry for each exact text payload, with up to three distinct bounded source clues from its occurrences; pins retain their existing behavior. AX pointers and coordinates are never identities.
- Destination insertion evidence outranks source context. Source context is included in the request only when associated; unknown stays explicit. Jev alone selects the item. A valid NONE or confidence at or below 70% uses the latest clipboard; errors paste nothing. The clipboard change lease and target validation remain in force. Native payload construction caps source context at 300 characters and marks any loss; the native request builder (and Python development reference) caps it at 300 UTF-8 bytes, can reduce that allowance to fit the complete request, and carries `source_context_truncated` through to Jev. The final request is capped at 24,000 serialized UTF-8 bytes with at most 52 candidates; this makes no provider token guarantee.

Example: copying `1200` from a Safari **Revenue** field, switching to Mail before polling, then copying `1200` from a **Deposit** field leaves two history occurrences. Smart Paste sees one `1200` candidate with both bounded field clues. Before this change the poll could label the first copy as Mail, and the second copy erased its source occurrence.

Coverage: native editable fields with AX selected text and labels can supply a matched field clue. Safari and other browsers can supply it only where the focused element exposes those attributes. Electron, office/spreadsheet cells, terminals and custom controls often expose no usable selection or label; they retain payload-only history unless the same narrow checks succeed. Clipboard writers need not emit ⌘C, and no supported universal arbitrary writer PID is assumed.
